System Design: How Rate Limiting Works in Production

🛡️

DDoS & Brute-Force Protection

Prevents malicious actors or buggy clients from overwhelming API gateways, authentication endpoints, and backend databases.

⚖️

Fair Resource Allocation

Ensures multi-tenant fairness so one heavy client or noisy neighbor cannot starve other legitimate users of compute or bandwidth.

💰

Cost Management

Caps consumption on expensive third-party external APIs (e.g. OpenAI, Stripe, Twilio) to avoid surprise infrastructure bills.

📐

Graceful Degradation

Returns standard HTTP 429 Too Many Requests with a Retry-After header, allowing well-behaved clients to implement exponential backoff.

Algorithm Burst Handling Memory Cost Pros Cons Typical Real-World Use Case
Token Bucket Excellent (Up to capacity) O(1) Easy to understand, allows short bursts without rejecting legitimate traffic, smooth refill. Requires tuning 2 parameters (capacity & refill rate). AWS API Gateway, Stripe API, Cloudflare, GitHub REST API
Leaky Bucket Smooths out (Queue based) O(Queue Size) Guarantees steady continuous outflow, perfect traffic shaping. Bursts fill queue; slow processing can cause high latency for delayed requests. Packet routing, video/audio streaming, database ingest pipelines
Fixed Window Counter Vulnerable (2x burst at edge) O(1) Very simple to implement in Redis with INCR and EXPIRE. A client can send limit requests at 00:59 and another at 01:00, exceeding limit 2x. Low-cost basic rate limits (e.g. 100 req/day per user tier)
Sliding Window Counter Fair O(1) Smooths the boundary burst issue of fixed windows with minimal memory. Approximation based on uniform request assumption. Modern microservice gateways (Envoy, Kong, Spring Cloud Gateway)

Atomic Lua Script Pattern for Redis Token Bucket:
-- KEYS[1]: bucket key (e.g. rate:user_123)
-- ARGV[1]: capacity, ARGV[2]: refill_rate, ARGV[3]: now_timestamp, ARGV[4]: cost
local data = redis.call("HMGET", KEYS[1], "tokens", "last_refill")
local tokens = tonumber(data[1]) or tonumber(ARGV[1])
local last = tonumber(data[2]) or tonumber(ARGV[3])
local elapsed = math.max(0, tonumber(ARGV[3]) - last)

-- Refill tokens
tokens = math.min(tonumber(ARGV[1]), tokens + elapsed * tonumber(ARGV[2]))

if tokens >= tonumber(ARGV[4]) then
    tokens = tokens - tonumber(ARGV[4])
    redis.call("HMSET", KEYS[1], "tokens", tokens, "last_refill", ARGV[3])
    redis.call("EXPIRE", KEYS[1], 3600)
    return {1, tokens} -- ALLOWED
else
    redis.call("HMSET", KEYS[1], "tokens", tokens, "last_refill", ARGV[3])
    return {0, tokens} -- REJECTED (429)
end
class TokenBucketRateLimiter:
    def __init__(self, capacity: float = 5.0, refill_rate: float = 1.0):
        self.capacity = float(capacity)
        self.refill_rate = float(refill_rate) # tokens added per second
        self.buckets = {}
        self.lock = threading.Lock()

    def acquire(self, key: str = "default", cost: float = 1.0):
        with self.lock:
            now = time.time()
            current_tokens = self._get_current_tokens(key, now)

            if current_tokens >= cost:
                # Allowed: decrement tokens
                current_tokens -= cost
                self.buckets[key] = {"tokens": current_tokens, "last_refill": now}
                return True, current_tokens, 0.0, self.capacity
            else:
                # Rate limited: calculate retry-after seconds
                needed = cost - current_tokens
                retry_after = round(needed / self.refill_rate, 2)
                return False, current_tokens, retry_after, self.capacity
